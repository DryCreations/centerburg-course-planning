# Week 4 Teacher Notes: Design Techniques

Teacher-facing pacing for Week 4. Student doc is `outline.md`; assignment is `project.md`; Tuesday's handout is
`handouts/tue-portfolio-update.md`; vocab is `vocab.md`. No new quiz this week: Friday is work time plus an
**independent, optional retake** of last week's Week 3 hierarchy and typography quiz for anyone who wants a
better score. **Decided: the retake score replaces the original, one time only, since this is the first quiz of
the year and many students had not yet learned how to study for one.**

## Pacing Guide

| Day | Activity | Notes |
|-----|----------|-------|
| Tue | Portfolio catch-up day. Students add last week's poster to their site's Unit 1.1 section, write about it using the reused sentence starters (`handouts/tue-portfolio-update.md`), and learn the real names for site parts (nav, header, page, footer). | Quick day on purpose: this closes the loop on last week's work before new content starts. Standard 7.1.2. |
| Wed | Post `vocab.md`. Explain UX versus UI. Introduce user journey mapping. Students list their portfolio's pages and map the journey. | Genuinely new content, standard 2.15.1. |
| Thu | Wireframing basics: boxes and labels, not finished visuals. Students sketch wireframes for each page on paper. | Keep it deliberately low-fidelity; structure before decoration. |
| Fri | Refine wireframes; peer review. Work time to finish. **Mention this is also open for an independent retake of last week's quiz.** | If wireframes are not done, they continue next week rather than being rushed; note progress here. |

## Assessment Notes

- Part A (portfolio update) is graded on completion: poster posted, description written, nav labeled.
- Part B (wireframes) graded per the rubric in `project.md`: complete page list and journey map, a wireframe
  per page, consistent navigation, and evidence of a real peer review.
- Retake policy is settled: replaces the original score, one time only.

## Differentiation

- **Finished early:** the extension (a rough digital layout of one wireframe).
- **Needs support:** provide a pre-made page list (Home, About, Projects, Contact) so the wireframing itself is
  the focus.

## Looking ahead

If the wireframe unit is not finished by Friday, it is fine to continue it into next week; a future unit
(Figma, closer UI design work) is planned to follow once this is done. Note the actual date it wraps once known.
