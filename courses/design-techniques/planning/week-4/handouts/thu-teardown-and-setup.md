# Thursday: Teardown Sheet and Figma Setup

**Design Techniques, Week 4, Thursday.** Two parts. Part 1 is the thinking, on paper. Part 2 is ten minutes
of setup at the end of class.

---

## Part 1: The Teardown

### Step 1: Pick your screen

Find one screen in an app or website that frustrates you. It has to pass all three:

- [ ] You can **screenshot** it
- [ ] It is **school appropriate**
- [ ] Something about it **actually bothers you**, and you can say what in one sentence

**Not sure what to pick?** A food ordering app, a school or district page, an athletics schedule, a streaming
service's browse screen, a store checkout, a game's settings menu, a ticket or airline page, a library
catalog, a recipe site buried in ads.

**Write your one sentence here:**

> The thing that bothers me about this screen is ______________________________________________

Get it approved before you mark it up.

### Step 2: Name the task

Every screen exists so somebody can do something.

> Somebody opens this screen because they want to ________________________________________________

### Step 3: Walk the journey

Number the steps a person takes to get that thing done. Then circle the step where it goes wrong.

| Step | What they do | What they see | Problem? |
|------|--------------|---------------|----------|
| 1 |  |  |  |
| 2 |  |  |  |
| 3 |  |  |  |
| 4 |  |  |  |
| 5 |  |  |  |

**It breaks at step ______ because ____________________________________________________________**

### Step 4: Mark up the screenshot

Print or sketch the screen, then draw arrows to **at least five** problems. Every annotation has to use design
language, not feelings. Use this table to check yourself:

| Instead of | Write |
|------------|-------|
| "It's cluttered" | "Nine things compete for attention with no clear first read" |
| "It's ugly" | "The type is set in three unrelated families with no reason" |
| "Hard to read" | "Light gray text on white fails contrast at that size" |
| "Confusing" | "The primary action looks identical to four secondary buttons" |
| "Too much stuff" | "Nothing is grouped, so related items read as unrelated" |
| "It's crowded" | "Every element is the same distance apart, so proximity says nothing" |

**Your terms from Week 3 all apply here:** hierarchy, focal point, visual weight, contrast, alignment,
proximity, whitespace, reading order.

### Step 5: The squint test

Squint at the screenshot until it blurs. What do you see first? Is that what the person actually came for?

> First thing I see when I squint: _____________________________________________________________
>
> What they actually came for: _________________________________________________________________
>
> Same thing? YES / NO. If NO, that is your headline finding.

## Part 2: Figma Setup (last 10 minutes)

You are only setting up today. You build tomorrow.

1. Go to **figma.com**
2. Click **Log in**, then **Continue with Google**, and use your **school account**
3. **Skip the tour.** If it offers to walk you through anything, decline it. You do not need it today.
4. Click **New design file**
5. Press **F** on the keyboard. That is the frame tool. A list of preset sizes appears on the right.
6. Under **Phone**, pick any option. Click once on the canvas to place it.
7. Double-click the frame's name above it and rename it to `Before-After: <your app name>`
8. Save happens automatically. Nothing to click.

**That is all for today.** If you have the frame and it has your name on it, you are done.

### If sign-in does not work

Do not sit and wait. Keep working on paper: finish your five annotations, then start sketching what the
screen should look like instead. You will get in tomorrow and you will be ahead of everyone who spent today
clicking around.

---

## If You Finish Early

1. Do a second teardown on a screen that works **well**. Name why it works. Good design is harder to see than
   bad design, and naming it is the real skill.
2. Find the same app's screen on a different device (phone vs desktop) and note what they moved, added, or
   removed, and why.
3. Start listing what you would **delete** from your screen. Most broken screens are broken because nothing
   was ever taken away.
