## Terms

| Term | Definition | Related Standard | DOK |
|------|-----------|-----------------|-----|
| **Algorithm** | A step-by-step set of instructions for solving a problem or completing a task | 5.6.6 | 1 |
| **Variable** | A named storage location in a program that holds a value which can change | 5.3.3 | 1 |
| **Boolean expression** | A statement that evaluates to either True or False — used in conditional and loop logic | 5.3.1 | 1 |
| **Truth table** | A grid that shows every possible combination of True/False inputs and the resulting output of a boolean operation (AND, OR, NOT) | 5.3.1 | 2 |
| **Conditional statement** | An if/elif/else block that executes different code depending on whether a condition is True or False | 5.3.4 | 1 |
| **For loop** | A control structure that repeats a block of code a fixed number of times, iterating over a sequence | 5.3.6 | 1 |
| **While loop** | A control structure that repeats a block of code as long as a condition remains True | 5.3.7 | 2 |
| **Function** | A named, reusable block of code that performs a specific task; can accept parameters and return values | 5.3.9 | 2 |
| **Parameter / Argument** | A parameter is a variable in a function definition; an argument is the actual value passed to that parameter when the function is called | 5.3.9 | 2 |
| **Syntax error** | An error caused by code that violates the language's grammar rules — Python will refuse to run | 5.4.6 | 1 |
| **Logic error** | An error where the code runs without crashing but produces wrong results — caused by incorrect algorithm design | 5.4.7 | 2 |
| **Indentation (Python)** | Python uses consistent indentation (usually 4 spaces) to define code blocks — unlike most languages that use braces {} | 5.3.3 | 1 |
| **Comment** | A line of code ignored by Python (starts with #) — used to explain what the code does for human readers | 5.5.5 | 1 |
| **Flowchart** | A diagram using standardized symbols (Start/End = rounded rectangle, Process = rectangle, Decision = diamond) to show the logical flow of a program | 5.6.7 | 2 |
| **Pseudocode** | A plain-language description of an algorithm's logic written to be human-readable rather than machine-executable | 5.6.6 | 2 |
| **SDLC (Software Development Lifecycle)** | The structured process for creating software: Plan → Design → Code → Test → Deploy → Maintain | 5.6.1 | 2 |
| **Agile** | An iterative SDLC methodology that works in short cycles (sprints), with frequent review and adaptation — used widely in tech companies | 5.6.12 | 2 |
| **Waterfall** | A linear SDLC methodology where each phase is completed before the next begins — used in large-scale engineering and regulated industries | 5.6.12 | 2 |
| **Version control** | A system that records changes to files over time — Git is the standard; tracks who changed what, when, and why | 5.7.1 | 2 |
| **Commit (Git)** | A saved snapshot of changes to a repository at a specific point in time, with a message describing what changed | 5.7.2 | 2 |
| **Repository** | A folder tracked by Git that stores the full history of all commits — can be local and/or hosted on GitHub | 5.7.3 | 1 |
| **Binary number** | A number expressed in base-2 (digits 0 and 1) — the fundamental language of all digital systems | 2.3.1 | 1 |
| **Hexadecimal** | A base-16 number system (0–9 and A–F) used commonly in color codes, memory addresses, and file headers | 2.3.2 | 2 |

## Key Distinctions

| Term 1 | Term 2 | Key Difference |
|--------|--------|---------------|
| Syntax error | Logic error | Syntax error prevents the code from running; logic error lets it run but produces wrong output |
| For loop | While loop | For loop iterates a fixed number of times; while loop continues until a condition becomes false |
| Agile | Waterfall | Agile = short iterative cycles with frequent feedback; Waterfall = linear phases completed in sequence |
| Comment | Variable | Comment is documentation for humans (#); variable is a data container for the computer |
| Commit | Repository | Repository is the full project history; a commit is one saved snapshot added to that history |

## Bell Ringer Prompts

1. What is the difference between a syntax error and a logic error? Which is harder to find, and why?
2. Write a truth table for: (A AND B) OR (NOT C) for all combinations of A, B, C.
3. Convert the binary number 1011 to decimal. Show your work.
4. What does it mean to "commit" in Git? What should a commit message include?
5. Draw the flowchart symbols for: Start, Process, Decision, End. Label each one.
