# Vocabulary: BPA Project Production

**Course:** 3D Techniques (145120)
**Unit:** 2.2 — BPA Project — Hard Surface Modeling or Animation
**Weeks:** 14–18

> Most vocabulary for this unit was introduced in Units 2.1 and 1.4. This list focuses on production workflow and BPA process terms.

---

## Terms

| Term | Definition | Related Standard | DOK |
|------|-----------|-----------------|-----|
| **Production schedule** | A living document tracking every task, milestone, and deadline — updated weekly during active production | 5.6.1 | 2 |
| **Asset** | Any individual file (model, texture, sound clip, animation rig) that is part of a larger project | 7.3.1 | 1 |
| **Render farm** | Multiple computers networked to split rendering workload — applicable to large Cycles renders or animation sequences | 7.6.6 | 2 |
| **Hero image** | The primary, best-quality rendered view of a 3D model — the image that leads a portfolio or BPA submission | 7.6.8 | 1 |
| **Wireframe render** | A render that shows edge structure without surface shading — used in BPA/portfolio submissions to show modeling complexity | 7.6.9 | 2 |
| **WSAP rubric** | The scoring document inside the BPA event WSAP that defines exactly what judges evaluate and how many points each element earns | 1.1.4 | 2 |
| **Research profile** | The written document in #425 Computer Modeling that establishes the industry context and purpose of the modeled object — required documentation | 1.1.3 | 2 |
| **Shot list** | For animation events (#440, V11): a document listing every shot by number, camera angle, duration, and content — precedes actual animation | 7.6.1 | 2 |
| **Role assignment** | In team events, each member has a specific defined responsibilities: director, modeler/animator, sound editor, etc. | 1.2.7 | 2 |
| **Iterative refinement** | The process of improving a project through repeated cycles of critique → revision → critique, not one-pass completion | 1.1.7 | 3 |
| **Critical feedback** | Specific, actionable commentary on a creative work focused on improvement — not vague praise or insults | 1.1.9 | 2 |
| **SDLC** (Software Dev Life Cycle) | Plan → Design → Build → Test → Deploy → Maintain — the structured project cycle that mirrors professional production workflows | 5.6.1 | 2 |
| **Accessibility** | Design practices that ensure content can be used by people with disabilities — contrast ratios, caption tracks, alt text | 7.3.11 | 2 |

## Bell Ringer Prompts

1. What is a hero image? Why does it matter more than the other renders in your submission?
2. A team #440 animation has no shot list. What production problems is this likely to cause?
3. What does iterative refinement mean in practice? How is it different from "fix it before you submit"?
4. How does the SDLC connect to your BPA project? Label which phase you're in this week.
5. Why does a wireframe render prove something to a BPA judge that a shaded render cannot?
