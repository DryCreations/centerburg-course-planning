## 4. Middle School CS 🔴: Trace bell ringers + a "level up" `if`

**Today's document:** `courses/middle-school-cs/planning/week-3/handouts/bell-ringer-wed.md`
**Post:** nothing required (run it on the board / in MakeCode). The handout has **copy-paste JavaScript** you can
drop into the **JS editor** and convert to **Blocks**.
**Go over:** two trace bell ringers (variables that change before an `if` checks them), then the **level-up**
example as the practical use of `if`. Then break out to add win/lose to the Decision Game.

### Slides, paste one block per slide

- **Slide 1, Entry:** "Read the code on the next slide. Write down **x**, **y**, and **what score shows**."
- **Slide 2, THE BELL RINGER (trace it):**
  ```
  let x = 10
  let y = 0
  y = x - 4
  x = x + y
  if (x >= 15) { y = 100 } else { y = 50 }
  info.setScore(y)
  ```
- **Slide 3, Answer:** "y = 10 - 4 = 6. x = 10 + 6 = 16. 16 >= 15 is TRUE → y = 100. Score = 100. `x` changed BEFORE the if checked it, order matters."
- **Slide 4, The gotcha:** "If a = 5 and we ask `a > 5`, that's FALSE (equal is not greater). `>` is not `>=`."
- **Slide 5, Cool example (paste + run):**
  ```
  let level = 1
  let score = 0
  game.onUpdateInterval(1000, function () {
      score += 1
      info.setScore(score)
      if (score >= 10 && level == 1) {
          level = 2
          game.splash("LEVEL 2!")
      }
  })
  ```
- **Slide 6, The trick:** "`&& level == 1` makes it level up ONCE. Delete that part and run it, it splashes 'LEVEL 2!' forever. THAT'S why the extra condition matters."
- **Slide 7, Break out:** "In your Decision Game, add a WIN (`if score >= …`) and a LOSE (`if lives <= 0`) condition. Playtest, keep the debug log."
