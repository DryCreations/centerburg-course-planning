**Today's documents:** `courses/design-techniques/planning/week-4/vocab.md`, `project.md`

**Go over:** UX vs UI, then map the user journey through their own portfolio. **New unit starts today.**

> Create one "As You Come In" slide for a high school design class. Big title: "As You Come In." Body: "Open

### Slide 2: Standards + Today

> Create one standards and agenda slide for a high school design class titled "Today: UX and UI." List this
> standard with its full text: 2.15.1 Understand the UX/UI design process (vision, journey mapping,
> wireframing, prototyping) for the targeted platform. Then a short agenda: 1) UX vs UI, 2) What a user journey

### Slide 3: UX vs UI

> Create one slide for a high school design class titled "UX vs UI." Two large definitions side by side. Left:
> "UX, user experience: how it FEELS to use something. Is it clear? Can I find what I need?" Right: "UI, user
> interface: the actual screens, buttons, menus, and visuals you interact with." Underneath: "Good UI with bad
> UX is a beautiful site nobody can navigate." One slide.

### Slide 4: The user journey

> Create one slide for a high school design class titled "The User Journey." Body: "A user journey is the PATH
> someone takes to get what they need. Example for a portfolio: a visitor lands on Home, wants to see if you do
> the kind of work they need, clicks Design Techniques, opens a project, then looks for how to contact you.
> Every step they cannot find is a place they leave." One slide, large text.

### Slide 5: Do Now

> Create one "Do Now" slide for a high school design class. Big title: "Do Now: Map Your Journey." Body: "On
> paper: 1) List every page your portfolio needs. 2) Number them in the order a visitor would actually move
> through them. 3) For each page, write one line: what does the visitor need from this page? Tomorrow you turn
> this into wireframes." Large, clean. One slide.

### Slide 6: Turn and Talk

> Create one "Turn and Talk" slide for a high school design class. Big title: "Turn and Talk: Walk the
> Journey." Body: "Trade journey maps with a partner. Read theirs out loud as if you were a visitor: 'I land
> here, then I want X, so I go here.' Where does it break down or get confusing? Tell them one page they are
> missing." One slide, large text.

### Slide 7: If You Finish Early

> Create one slide for a high school design class titled "Finished Your Map?" Numbered list: 1) Sketch a rough
> box-and-label layout for your Home page, you will refine it tomorrow. 2) Find a real portfolio site online and
> map ITS user journey in three steps. 3) Write down one thing that site does better than yours. One slide.

### Slide 8: Before You Leave

> Create one "Exit" slide titled "Before You Leave." Body: "You should have a page list and a numbered user
> journey. Tomorrow: wireframing, turning that map into actual page sketches. Friday is work time plus the
> optional quiz retake." One slide, large text.

### Slide 3: The go/no-go call

> Create one slide for a high school drone class titled "Go or No-Go, For Real." Body: "Pull the current METAR

### Slide 4: Roles and the order of operations

> Create one slide for a high school drone class titled "Your Role Today." Body: "PILOT: flies, calls out every
> move before making it. VISUAL OBSERVER: eyes on the aircraft the whole time, never on a screen. LOGGER: times,

> Create one "Do Now" slide for a high school drone class. Big title: "Do Now: Brief and Preflight." Body:

### Slide 6: While You Are Not Flying

> Create one slide for a high school drone class titled "Not Your Turn? You Still Have a Job." Numbered list:
> 1) Stay behind the spectator line. 2) Watch the shot and write one note: did it match the plan? 3) Time the

### Slide 7: If Weather Scrubs It

> Create one slide for a high school drone class titled "If We Cannot Fly." Body: "A no-go is a real outcome,

### Slide 8: Before You Leave

## 4. Middle School CS: Variables and the win condition

**Today's documents:** `courses/middle-school-cs/planning/week-4/handouts/tilemap-maze-guide.md` (Part 5),
`project.md`
**Go over:** explicitly, how to count collected items with a variable and end the game with an if. **Quiz is
tomorrow, if statements only, not tile maps.**

### Slide 1: As You Come In

> Create one "As You Come In" slide for a middle school computer science class. Big title: "As You Come In."
> Body: "Open your maze project and run it. Drive at a wall to check your collision still works. If your walls
> leak, fix that first, we build on top of the maze today." Large, clean, minimal. One slide.

### Slide 2: Standards + Today

> Create one agenda slide for a middle school computer science class titled "Today: Count What You Collect."
> Text: Today's skills are variables and conditionals, from the Ohio CS standards for Algorithmic Thinking and
> Programming. Agenda: 1) Place items in your maze, 2) Use a VARIABLE to count them, 3) Use an IF to decide
> when you win. Add a box: "Quiz TOMORROW on if statements and everything before. NOT tile maps." Large
> readable text. One slide.

### Slide 3: A variable is a counter

> Create one slide for a middle school computer science class titled "A Variable Can Count." Body: "You already
> know a variable is a named container that holds a value. When you use one to keep track of how many times
> something happened, it is called a COUNTER. Your maze needs a counter for how many items the player has
> picked up." One slide, large readable text.

### Slide 4: The code, line by line

> Create one slide for a middle school computer science class titled "The Whole Thing." Show this code in a
> monospace box: "let keys = 0" then "on overlap Player with Food:" then indented "otherSprite.destroy()",
> "keys += 1", "info.setScore(keys)", "if keys == 5: game over WIN". One slide, large readable text.

### Slide 5: Read it out loud

> Create one slide for a middle school computer science class titled "What Each Line Does." Present as a list:
> "let keys = 0" makes the counter and starts it at zero; "on overlap" runs every time the player touches an
> item; "destroy" removes the item you just touched; "keys += 1" adds one to your count, this is the variable
> doing its job; the "if" checks whether you have them all yet. One slide, large legible text.

### Slide 6: The most common bug

> Create one slide for a middle school computer science class titled "Why Your Win Never Happens." Body: "The
> number in your if statement has to MATCH how many items you actually placed. If your if says 5 and you put 7
> items in the maze, the player can never trigger the win, because the counter blows past 5 without ever
> equaling it at the right moment. Count your items. Fix the number." One slide, large text.

### Slide 7: Do Now

> Create one "Do Now" slide for a middle school computer science class. Big title: "Do Now: Make It Winnable."
> Body: "1) Place your items around the maze. 2) Add the counter variable. 3) Add the on-overlap that destroys
> the item and adds one. 4) Add the if that ends the game as a win. 5) TEST IT: collect everything and confirm
> you actually win. Count your items and match the number in your if." Large, clean. One slide.

### Slide 8: Turn and Talk

> Create one "Turn and Talk" slide for a middle school computer science class. Big title: "Turn and Talk: Can
> They Win It?" Body: "Trade seats and play your partner's maze all the way through. Can you collect everything
> and actually trigger the win? If the win never fires, tell them, and check their number against how many
> items are really in the maze." One slide, large readable text.

### Slide 9: If You Finish Early

> Create one slide for a middle school computer science class titled "Winnable? Level It Up." Numbered list: 1)
> Make the maze harder, dead ends and longer paths. 2) Swap your tile art to a different theme. 3) Add an enemy
> that costs you a life with an if. 4) Add a second level that loads a new tile map. 5) Add a timer that ends
> the game if it runs out. One slide.

### Slide 10: Before You Leave

> Create one "Exit" slide titled "Before You Leave." Body: "Your maze should be winnable: items placed, counter
> counting, and an if that ends the game. Tomorrow: the QUIZ on if statements and everything before, then work
> time on the maze. Review your if statement notes tonight." One slide, large text.
